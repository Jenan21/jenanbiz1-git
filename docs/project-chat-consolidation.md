## قرارات ثابتة للمشروع

- المستودع الصحيح للعمل الحالي هو `https://github.com/Jenan21/jenanbiz1-git`.
- مسار العمل المحلي في VS Code هو `c:\Users\JEN21\jenanbiz1-git`، وتوجد نسخة مشروع على سطح المكتب في `c:\Users\JEN21\OneDrive\سطح المكتب\jenanbiz1`.
- Vercel مؤقت للاختبار فقط، والمجال النهائي `jenanbiz.sa` سيُستعاد لاحقاً أو يُنقل إلى استضافة دائمة يختارها المالك.
- لا يتم وصف أي قسم بأنه `10/10` إلا بعد فحص وظيفي واختبارات واضحة؛ نجاح الواجهة وحده لا يعني اكتمال الخدمة إنتاجياً.
- أي تكامل يحتاج مزوداً خارجياً يبقى جاهزاً برمجياً ومؤجلاً حتى توفير الحساب/العقد/الأسرار من المالك.
- لا تُحفظ أو تُعرض مفاتيح API في الدردشة أو في المستندات. أي مفتاح ظهر في محادثة يجب تدويره وإبطاله.

## حالة التشغيل المثبتة من الدردشات

- تم اختبار OpenAI الحقيقي عبر `LIVE-ACCEPTANCE-001` بعد إصلاح إعداد المفتاح المحلي، ونجح حفظ سجلات التنفيذ والتكلفة والدليل والتعلم والمعرفة المشتركة في PostgreSQL.
- سبق أن وصل اختبار E2E الداخلي إلى `77/77` بنجاح لمسارات المصادقة، الإدارة، الملفات، المشاريع، برامج المنشآت، الأكاديمية، والسوق.
- التشغيل التجريبي المحلي قُدّر سابقاً بحوالي `88%` عند احتساب التكاملات الخارجية غير المربوطة.
- Redis الإنتاجي في Vercel Marketplace مفعّل لاحقاً بحسب ذاكرة المستودع، وتم التحقق من `/api/health/ready` بأن `rateLimit: true`.

## التكاملات الخارجية المؤجلة

- بوابة دفع حقيقية.
- مزود خرائط تجاري مرخّص.
- منصات إعلانات وتسويق فعلية.
- مزود تمويل أو تحقق ائتماني.
- تخزين ملفات سحابي إنتاجي عند الحاجة.
- مصادر أسعار/تكاليف وسكان/قوة شرائية موثقة حسب الدولة.
- خط عربي مرخص ومحرك PDF يدعم RTL بشكل احترافي.

## قواعد العمل المقبلة

- كل قسم يُفحص محلياً ثم نوعياً قبل اعتباره جاهزاً؛ لا يُرفع على أنه مكتمل إذا كان تقييمه أقل من الهدف المتفق عليه.
- عند وجود عمل Codex أو فرع UI خارجي، يتم فحصه كمسار منفصل ثم اختيار الأفضل، ولا يتم `merge` أو `cherry-pick` عشوائياً فوق `main`.
- الأسرار تُضاف من المستخدم داخل `.env` أو إعدادات النشر فقط، ولا تُرسل في المحادثة.
- قبل النشر الحقيقي على `jenanbiz.sa` يجب تشغيل فحص شامل: `lint`، `typecheck`، `build`، الاختبارات المستهدفة، وE2E للأقسام المراد اعتمادها.
- لا يتم تنفيذ `git add` أو `commit` أو `push` في هذا المستودع إلا بعد عرض النتيجة والحصول على موافقة صريحة جديدة.

لا توجد أداة متاحة حالياً لإغلاق عناصر سجل الدردشة الظاهرة في واجهة VS Code من داخل هذا الملف. بعد حفظ هذه الخلاصة، يمكن إغلاق الدردشات المفحوصة يدوياً من واجهة Chat History، مع إبقاء هذه الوثيقة كمرجع واحد للمشروع.
